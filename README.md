# SynTech Music

เปิดเพลง YouTube พร้อมกันหลายเครื่องในวง LAN เดียวกัน เสียงออกที่เครื่องเดียว ที่เหลือเป็นรีโมท

เครื่องที่ต่อลำโพงหรือทีวีทำหน้าที่เป็น **โฮสต์** — โหลด YouTube player จริงและเป็นเครื่องเดียวที่มีเสียง
เครื่องอื่นเปิดเว็บเดียวกันจากมือถือหรือโน้ตบุ๊กเพื่อค้นหาเพลง เพิ่มคิว จัดลำดับ ข้าม วนซ้ำ และปรับเสียงลำโพง

สถานะห้องทั้งหมดอยู่ที่เซิร์ฟเวอร์ ไม่ได้อยู่ที่เบราว์เซอร์ ทุกคำสั่ง broadcast ผ่าน WebSocket ทันที
ทุกจอจึงเห็นคิวและตำแหน่งเพลงตรงกัน ไม่ต้องรีเฟรช

ไม่ต้องใช้ YouTube API key

---

## เริ่มใช้งาน

```bash
pip install -r requirements.txt
python run.py
```

`run.py` จะพิมพ์ URL ทั้งของเครื่องตัวเองและไอพีในวง LAN ให้อัตโนมัติ

| ขั้น | ทำอะไร |
|:--:|---|
| 1 | เครื่องที่ต่อลำโพง เปิด `http://localhost:8000` แล้วกด **+ สร้างห้องใหม่** |
| 2 | เครื่องอื่น เปิด `http://<ไอพี LAN>:8000` แล้วกดการ์ดห้องที่ขึ้นบนหน้าจอ |
| 3 | พิมพ์ชื่อเพลงในช่องค้นหา หรือวางลิงก์ YouTube / Spotify แล้วกด **ค้นหา** |

ครั้งแรกที่มีเครื่องอื่นเข้ามา Windows Firewall จะถามสิทธิ์ ต้องอนุญาต **Private networks**
ไม่งั้นเครื่องในวง Wi-Fi เดียวกันจะเข้าไม่ได้

ต้องใช้ Python 3.12 ขึ้นไป dependency มีแค่ FastAPI กับ uvicorn

## ความสามารถ

| ฟังก์ชัน | ทำงานยังไง |
|---|---|
| เสียงออกที่โฮสต์เครื่องเดียว | เครื่องรีโมทไม่โหลด YouTube player เลย จึงไม่มีเสียงซ้อนและไม่กินเน็ต/แบต |
| ย้ายลำโพงได้ทุกเมื่อ | กด "ย้ายลำโพงมาเครื่องนี้" เครื่องเดิมกลายเป็นรีโมททันที ไม่ต้องรีโหลดหน้า |
| ค้นหาสดขณะพิมพ์ | หน่วง 550ms แล้วยิงค้นหา ใช้ `AbortController` ยกเลิกคำค้นเก่า ส่งกลับ 12 ผลลัพธ์ |
| ดึงทั้ง Playlist และ Radio Mix | ลิงก์ `list=PL...` และ `list=RD...` ดึงได้สูงสุด 100 เพลงต่อครั้ง |
| นำเข้าจาก Spotify | วางลิงก์ track / playlist / album อ่านชื่อเพลงจากหน้า embed แล้วไปหาคลิปที่ตรงกันบน YouTube |
| Auto DJ | คิวหมดแล้วหาเพลงต่อเอง เลือกได้ว่า **แนวเดียวกัน** (สุ่มจากเพลย์ลิสต์สาธารณะที่มีเพลงนี้ หรือ YouTube Mix ถ้าอ่านได้) หรือ **ศิลปินเดิม** กรองเพลงซ้ำและคลิปที่ไม่ใช่เพลงออก **ปิดไว้เป็นค่าเริ่มต้น** |
| โหมดวนซ้ำ | 3 ระดับ ไม่ซ้ำ → วนซ้ำคิว → วนซ้ำเพลงนี้ |
| ลากจัดลำดับคิว | ลากที่ `≡` ใช้ได้ทั้งเมาส์และนิ้ว |
| ประวัติเพลงที่เล่นจบ | เก็บ 15 เพลงล่าสุด กดเพิ่มกลับเข้าคิวได้ |
| กระดานสถิติ DJ | นับจำนวนเพลงและเวลารวมที่แต่ละคนเปิด จัดอันดับในห้อง |
| ทุกคนปรับเสียงลำโพงได้ | สไลเดอร์ส่งผลที่ลำโพงโฮสต์ มี sequence number กันค่าเก่าทับค่าใหม่ |
| ล็อกสิทธิ์เฉพาะโฮสต์ | ปิดสวิตช์ "ให้ทุกเครื่องคุมเพลง" แล้วเหลือแค่โฮสต์ที่สั่งได้ |
| ประกาศเสียงตามสาย | อัดเสียงพูดหรือเลือกไฟล์เสียง ส่งไปทุกห้องพร้อมกัน เพลงหรี่ลงเอง เล่นวนได้ 1-3 รอบ |
| PWA | Add to Home Screen บน iOS/Android ใช้เป็นแอปไร้ขอบได้ |

## สถาปัตยกรรม

```mermaid
flowchart LR
    S["FastAPI Server<br/>เจ้าของสถานะห้อง<br/>คิว · เวลา · เสียง · ประวัติ · สถิติ"]
    H["เครื่องโฮสต์<br/>YouTube IFrame Player<br/>เสียงออกที่นี่"]
    R1["รีโมท — มือถือ"]
    R2["รีโมท — โน้ตบุ๊ก"]
    Y(["YouTube / Spotify<br/>ค้นหา · oEmbed · Radio Mix · embed page"])

    H <-->|WebSocket| S
    R1 <-->|WebSocket| S
    R2 <-->|WebSocket| S
    S -.->|HTTP scrape| Y
```

เซิร์ฟเวอร์เก็บ **ตำแหน่งเพลงเป็น timestamp** ไม่ใช่ตัวนับที่เดินเอง ฝั่งไคลเอนต์คำนวณตำแหน่งจริงจาก
เวลาเซิร์ฟเวอร์ที่วัด offset ไว้ แล้ว `sync()` เทียบทุก 2 วินาที ถ้าเพี้ยนเกินเกณฑ์ค่อย seek
วิธีนี้ทำให้เครื่องที่เข้าห้องช้าเริ่มเล่นตรงตำแหน่งเดียวกับคนอื่นได้เลย

### HTTP endpoints

| Endpoint | ใช้ทำอะไร |
|---|---|
| `GET /` | หน้าเว็บ |
| `GET /api/new-room` | ขอรหัสห้องใหม่ |
| `GET /api/rooms` | รายชื่อห้องที่เปิดอยู่ ใช้วาดการ์ดหน้าแรก |
| `GET /api/search?q=` | ค้นหาเพลง |
| `WS /ws/{code}` | ช่องทางหลักทั้งหมด — เพิ่ม/ลบ/ย้ายคิว, play/pause/seek/next, เสียง, สิทธิ์, ประกาศ |
| `POST /api/announce-audio` | อัปโหลดคลิปเสียงประกาศ (body ดิบ + Content-Type ของคลิป) คืน `clipId` |
| `GET /api/announce-audio/{clipId}` | ลำโพงดึงคลิปไปเล่น คลิปอยู่ในหน่วยความจำชั่วคราว 10 นาที |

## ประกาศเสียงตามสาย

ใช้เมื่อต้องการแทรกเสียงประกาศไปทุกห้องพร้อมกัน เช่น เรียกประชุม แจ้งเวลาปิดงาน แจ้งเหตุฉุกเฉิน
ประกาศเป็น**เสียงล้วน** — อัดเสียงพูดเองในเบราว์เซอร์ หรือเลือกไฟล์เสียงที่เตรียมไว้จากเครื่อง ไม่มีการพิมพ์ข้อความหรือเสียงอ่านสังเคราะห์

```mermaid
sequenceDiagram
    participant P as ผู้ประกาศ (เครื่องไหนก็ได้)
    participant S as Server
    participant H1 as ลำโพงห้อง A
    participant H2 as ลำโพงห้อง B

    P->>S: POST /api/announce-audio (คลิป) → clipId
    P->>S: announce {clipId, clipMs, repeat, scope, chime}
    S->>S: cooldown 10 วิ + gap 3 วิ + เวลาล้าง = clipMs × repeat
    S-->>H1: state {announcement}
    S-->>H2: state {announcement}
    Note over H1,H2: หรี่เพลงเหลือ 12 → ตุ๊งแต๊ง → เล่นคลิปวนตามจำนวนรอบ
    Note over H1,H2: เล่นจบคืนระดับเสียงเดิมทันที
    S-->>H1: state {announcement: null}
    S-->>H2: state {announcement: null}
```

| ขั้น | ทำอะไร |
|:--:|---|
| 1 | กดปุ่ม **ประกาศ** บนแถบหัวของหน้าห้อง |
| 2 | กด **อัดเสียงพูดเอง** แล้วพูด หรือกด **เลือกไฟล์เสียงจากเครื่อง** (mp3 / m4a / wav / ogg) ฟังทวนได้ก่อนส่ง |
| 3 | เลือกว่าจะส่ง "ทุกห้อง" หรือ "เฉพาะห้องนี้" และจะให้เล่นวน 1, 2 หรือ 3 รอบ |
| 4 | กด **ส่งประกาศ** |

ไม่มีรหัสผ่าน ทุกเครื่องประกาศได้ ตามแนวเดียวกับส่วนอื่นของแอป
เหลือไว้แค่ตัวกันความผิดพลาดโดยไม่ตั้งใจ — คนเดิม 1 ครั้งต่อ 10 วินาที และเว้นห่างประกาศก่อนหน้า 3 วินาที

### พฤติกรรมที่ควรรู้

| เรื่อง | เป็นแบบนี้ | เพราะอะไร |
|---|---|---|
| การหรี่เพลง | หรี่เฉพาะที่ลำโพง ไม่เขียนทับระดับเสียงของห้อง | ถ้าเขียนทับ แถบเสียงบนมือถือทุกเครื่องจะกระตุก และถ้ามีคนเลื่อนแถบพอดีค่าจะตีกัน |
| มีคนเลื่อนเสียงตอนประกาศ | ระบบเคารพค่าใหม่ แต่ยังหรี่อยู่ ไม่ดังเกินค่าที่ตั้ง | หรี่คำนวณเป็น `min(12, ค่าที่ผู้ใช้ตั้ง)` ใหม่ทุกครั้งที่ sync |
| เล่นวนหลายรอบ | ลำโพงเล่นคลิปซ้ำเอง เว้น 0.7 วินาทีระหว่างรอบ กดหยุดได้ทุกเมื่อ | จำนวนรอบติดไปกับตัวประกาศ ทุกห้องจึงเล่นเท่ากัน |
| ลำโพงหลุดกลางประกาศ | เครื่องที่มารับช่วงจะหรี่ตาม แต่ไม่เล่นซ้ำถ้าเหลือเวลาน้อยกว่า 1 วินาที | ประกาศเก็บใน state ของห้อง ไม่ใช่ event ครั้งเดียวจบ |
| ประกาศค้าง | เซิร์ฟเวอร์ล้างให้เองเมื่อหมดเวลา (ความยาวคลิป × รอบ + 3 วินาที) | เผื่อกรณีลำโพงหลุดก่อนเล่นจบ ไม่งั้นแบนเนอร์จะค้างถาวร |
| ยิงรัว | คนเดิม 1 ครั้งต่อ 10 วินาที และเว้นห่างจากประกาศก่อนหน้า 3 วินาที | กันสแปมและกันสองประกาศทับกัน |
| ความยาวคลิป | ไม่เกิน 60 วินาที อัดครบแล้วหยุดให้เอง ไฟล์ที่ยาวกว่าจะถูกปฏิเสธตั้งแต่ตอนเลือก | นานกว่านี้เพลงโดนหรี่นานเกินไป ฝั่งเว็บวัดความยาวไฟล์ด้วย `<audio>` ก่อนอัปโหลด |
| ขนาดไฟล์ | ไม่เกิน 12 MB | wav 60 วิ สเตอริโอราว 10.5 MB ส่วน mp3 / opus เล็กกว่ามาก |
| ที่เก็บคลิป | หน่วยความจำของเซิร์ฟเวอร์ ลบเองหลัง 10 นาที เก็บได้ไม่เกิน 50 คลิป | ไม่เขียนลงดิสก์ — บน Render ดิสก์หายทุกครั้งที่ deploy อยู่แล้ว และคลิปไม่มีค่าควรเก็บ |
| เวลาล้างประกาศ | ใช้ความยาวคลิปที่ฝั่งอัดวัดไว้ (`clipMs`) | ไฟล์ webm จาก MediaRecorder ไม่มี duration ในหัวไฟล์ เซิร์ฟเวอร์อ่านเองไม่ได้ |
| ชนิดไฟล์ | Chrome/Edge/Firefox อัดเป็น webm/opus, Safari อัดเป็น mp4/AAC ไฟล์จากเครื่องรับ mp3 / m4a / wav / ogg / aac / flac | ลำโพงที่เป็น Safari รุ่นเก่าอาจเล่น webm / ogg ไม่ได้ ระบบจะขึ้น toast แล้วเหลือแค่แบนเนอร์ ถ้าจะให้ชัวร์ใช้ mp3 หรือ m4a |
| ไมค์ | ใช้ได้เฉพาะ secure context (`https://` หรือ `localhost`) | ข้อบังคับของเบราว์เซอร์ — บน Render เป็น https อยู่แล้ว ส่วน LAN แบบ http ปุ่มจะบอกว่าอัดไม่ได้ แต่เลือกไฟล์จากเครื่องยังได้ |

> **ไมค์สดแบบเรียลไทม์ยังไม่ทำ** — ต้องใช้ WebRTC หรือสตรีมผ่าน WebSocket ซึ่งซับซ้อนกว่ามาก มีดีเลย์
> และเสี่ยงเสียงหอนถ้าผู้พูดอยู่ใกล้ลำโพง แบบอัดแล้วส่งครอบคลุมการใช้งานจริงได้แล้ว

## Auto DJ

เมื่อคิวเหลือเพลงสุดท้าย Auto DJ จะหาเพลงถัดไปมาต่อให้เอง เลือกโหมดได้ที่เมนูข้างปุ่ม Auto DJ

| โหมด | หาเพลงจากไหน | หมายเหตุ |
|---|---|---|
| แนวเดียวกัน (ค่าเริ่มต้น) | 1. YouTube Mix ของเพลงล่าสุด ถ้าเซิร์ฟเวอร์อ่านได้ 2. เพลย์ลิสต์สาธารณะที่มีเพลงล่าสุดอยู่ เพลงที่โผล่หลายเพลย์ลิสต์มีโอกาสถูกเลือกมากกว่า และพยายามเลี่ยงศิลปินเดิมเพื่อให้หลากหลาย | บน Render YouTube ตอบ HTTP 429 ให้หน้า watch จึงอ่าน Mix ไม่ได้ ใช้ข้อ 2 เสมอ |
| ศิลปินเดิม | เพลย์ลิสต์สาธารณะที่ค้นด้วยชื่อช่องของเพลงล่าสุด แล้วเลือกเฉพาะคลิปจากช่องเดียวกัน | ชื่อช่องมาจาก oEmbed เทียบแบบตัดคำว่า Official / VEVO / Topic ออก |

ทั้งสองโหมดกันเพลงซ้ำด้วยการเทียบชื่อเพลง (คนละคลิปของเพลงเดิมก็ไม่เอา) กับเพลงที่กำลังเล่น ในคิว และ 10 เพลงล่าสุด
และไม่ค้นหาด้วยชื่อเพลงตัวเองอีกแล้ว เพราะวิธีนั้นได้แต่เพลงเดิมคนละคลิปกลับมา ถ้าหาไม่ได้จริง ๆ ระบบจะแจ้งในห้อง

## สิ่งที่วางลงช่องค้นหาได้

| วางอะไร | ระบบทำอะไรต่อ |
|---|---|
| ชื่อเพลง | ค้นหาสด แสดงปก ความยาว ชื่อช่อง ให้เลือกก่อนเพิ่ม |
| ลิงก์คลิป | ตรวจว่าฝังเล่นได้จริงก่อน ถ้าเล่นไม่ได้จะเสนอคลิปอื่นที่ใกล้เคียง |
| `list=PL...` | ดึงเพลงในเพลย์ลิสต์เข้าคิว สูงสุด 100 เพลง |
| `list=RD...` | ดึงเพลงจาก Radio Mix เข้าคิว |
| ลิงก์ Spotify | อ่านชื่อเพลงจากหน้า embed แล้วหาคลิปที่ตรงกันบน YouTube ใช้ได้เฉพาะเพลย์ลิสต์สาธารณะ |

## ปัญหาที่เจอบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| เครื่องอื่นเปิดเว็บไม่ได้ | เช็คว่าอยู่ Wi-Fi วงเดียวกัน และ Firewall อนุญาตพอร์ต 8000 แบบ Private network แล้ว |
| หน้าเว็บไม่เห็นของใหม่ | กด `Ctrl + Shift + R` ล้างแคช (ไฟล์ static มี `?v=` กันแคชอยู่แล้ว แต่บางเบราว์เซอร์ดื้อ) |
| `[WinError 10048] address in use` | พอร์ต 8000 มีโปรแกรมอื่นใช้อยู่ ปิดตัวเดิมก่อนแล้วรัน `python run.py` ใหม่ |
| ขึ้น "เบราว์เซอร์บล็อกเสียง" | เบราว์เซอร์ไม่ให้เล่นเสียงก่อนผู้ใช้แตะหน้าจอ กดปุ่มบนจอหรือแตะที่ไหนก็ได้หนึ่งครั้ง |
| นำเข้า Spotify ไม่สำเร็จ | เพลย์ลิสต์เป็นแบบส่วนตัว หน้า embed จึงอ่านไม่ได้ ต้องตั้งเป็น public ก่อน |
| ประกาศขึ้นแบนเนอร์แต่ไม่มีเสียง | เบราว์เซอร์ของเครื่องลำโพงเล่นชนิดไฟล์นั้นไม่ได้ (มักเป็น Safari กับ webm/ogg) ลองอัดจาก Chrome หรือใช้ไฟล์ mp3 / m4a แทน |
| ปุ่มอัดเสียงบอกว่าอัดไม่ได้ | เปิดผ่าน `http://` ตามไอพี LAN ซึ่งเบราว์เซอร์ไม่ให้ใช้ไมค์ ใช้ลิงก์ https ของ Render หรือเลือกไฟล์เสียงจากเครื่องแทน |
| Auto DJ ไม่ทำงาน | ค่าเริ่มต้นปิดอยู่ ต้องกดปุ่ม Auto DJ ให้ขึ้นสถานะ "เปิด" และต้องมีประวัติเพลงอย่างน้อย 1 เพลงเป็น seed ถ้าขึ้นว่า "หาเพลงต่อไม่ได้" แปลว่าเพลงนั้นไม่มีในเพลย์ลิสต์สาธารณะเลย ลองเปลี่ยนโหมดหรือเพิ่มเพลงเอง |
| Auto DJ เล่นแต่เพลงเดิมคนละคลิป | เป็นบั๊กเวอร์ชันก่อน (ค้นหาด้วยชื่อเพลงตัวเองเมื่ออ่าน Mix ไม่ได้) เวอร์ชันนี้เปลี่ยนไปใช้เพลย์ลิสต์สาธารณะแทนแล้ว |

## หมายเหตุการพัฒนา

- ข้อมูลห้องเก็บในหน่วยความจำล้วน ไม่มีฐานข้อมูล รีสตาร์ตเซิร์ฟเวอร์แล้วห้องหายหมด
- การค้นหาและดึงเพลย์ลิสต์ใช้วิธี scrape หน้าเว็บ YouTube ไม่ได้เรียก Data API
  ถ้า YouTube เปลี่ยนโครงสร้างหน้า ตัว parser ใน `youtube.py` จะต้องแก้ตาม
- ออกแบบมาสำหรับวง LAN ที่เชื่อใจกันได้ ไม่มีระบบยืนยันตัวตน ใครรู้รหัสห้องก็เข้าได้
- ระบบประกาศยิงข้ามห้องได้ จึงกระทบคนที่ไม่ได้อยู่ห้องเดียวกับผู้ส่ง แต่เปิดให้ทุกคนใช้ได้ตามที่ตกลงกันไว้
  ถ้าวันหนึ่งต้องจำกัดสิทธิ์ ต้องตรวจฝั่งเซิร์ฟเวอร์ใน `handle_announce()` ไม่ใช่ซ่อนปุ่มฝั่งหน้าเว็บ
  เพราะซ่อนปุ่มกันคนที่ยิง WebSocket ตรงไม่ได้

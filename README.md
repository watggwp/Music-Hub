# SynHub Music — ระบบเปิดเพลงพร้อมกัน

เปิดเพลง YouTube ให้ทุกคนในห้องเห็นตรงกัน โดย **เสียงออกที่เครื่องโฮสต์เครื่องเดียว**
เครื่องที่เหลือเป็นรีโมทคุมเพลง — เพิ่มเพลง ข้ามคิว ปรับเสียงลำโพงของโฮสต์ได้จากมือถือตัวเอง
เซิร์ฟเวอร์เป็นเจ้าของสถานะทั้งหมดแล้ว broadcast ผ่าน WebSocket ทันทีที่มีคนกดอะไร

## วิธีรัน

```bash
pip install -r requirements.txt
python run.py
```

**เครื่องที่จะเป็นลำโพง** (ต่อทีวี/ลำโพงไว้): เปิด http://localhost:8000 → กด **สร้างห้องใหม่**

**เครื่องอื่น**: เปิดหน้าเดียวกัน จะเห็นห้องที่เปิดอยู่เป็นการ์ด กดการ์ดเข้าได้เลย ไม่ต้องพิมพ์รหัส
(รายการห้องอัปเดตเองทุก 3 วินาที) หรือเปิดลิงก์จากปุ่ม *คัดลอกลิงก์* ก็เข้าห้องนั้นทันที

เครื่องอื่นในวง LAN เข้าที่ `http://<ไอพีเครื่องนี้>:8000` (`run.py` พิมพ์ไอพีให้ตอนเริ่ม)
ครั้งแรก Windows Firewall จะถามสิทธิ์ — ต้องกดอนุญาต **Private network**

## โครงสร้าง

| ไฟล์ | หน้าที่ |
|---|---|
| `app/server.py` | FastAPI + WebSocket endpoint, สิทธิ์ควบคุม, broadcast สถานะ |
| `app/room.py` | สถานะห้อง: คิวเพลง, ตำแหน่งเพลง, โฮสต์ |
| `app/youtube.py` | แยกลิงก์, ตรวจว่าฝังได้ไหม, ค้นหาด้วยชื่อ, อ่านรายชื่อเพลงใน playlist |
| `static/app.js` | YouTube IFrame API (เฉพาะโฮสต์) + ตัวซิงก์เวลาและแก้ drift |

## ระบบซิงก์ทำงานยังไง

1. `Room` เก็บตำแหน่งเพลงเป็นคู่ `(position, monotonic_mark)` — เวลาจริง ณ ตอนนี้คำนวณสด ๆ
   ไม่ใช่ตัวนับที่ต้องคอย tick จึงไม่มีทางเพี้ยนสะสม
2. ทุก broadcast แนบ `ts` (เวลาเซิร์ฟเวอร์) มาด้วย ไคลเอนต์วัด clock offset จาก ping/pong
   ทุก 15 วินาที แล้วคำนวณตำแหน่งเป้าหมาย = `position + (serverNow - ts)`
3. ทุก 2 วินาทีไคลเอนต์เทียบเวลาเพลงจริงกับเป้าหมาย ถ้าเพี้ยนเกิน **1.2 วินาที** ค่อย `seekTo`
   (เผื่อไว้กว้างพอไม่ให้กระตุกจากอาการเน็ตสะดุดชั่วครู่)

## คิวเพลง

คิว**ไหลจากหัวแถว** — `queue[0]` คือเพลงที่กำลังเล่น เล่นจบหรือกดข้ามแล้วเพลงนั้นหลุดออกจากคิวไปเลย
ไม่มีตัวชี้ index ให้สับสน (ปุ่ม ⟲ คือเริ่มเพลงนี้ใหม่ ไม่ใช่ย้อนไปเพลงก่อนหน้า เพราะเพลงเก่าไม่อยู่ในคิวแล้ว)

ปุ่มในแต่ละแถวของคิว:

| ปุ่ม | ทำอะไร |
|---|---|
| ≡ | **ลากย้ายไปตำแหน่งไหนก็ได้** (ดูด้านล่าง) |
| ▶ | เล่นเพลงนี้เลย — เพลงที่เล่นอยู่ถูกดันไปเป็นเพลงถัดไป ไม่หายไปจากคิว |
| ✕ | เอาออกจากคิว |

### ลากย้ายลำดับ

ใช้ pointer event จึงลากได้ทั้งเมาส์บนคอมและนิ้วบนมือถือ (`touch-action: none` ที่ตัวจับ
กันหน้าเว็บเลื่อนตามนิ้ว) มีเส้นสีฟ้าบอกตำแหน่งที่จะวาง และเลื่อนลิสต์ให้เองเมื่อลากใกล้ขอบ

รายละเอียดที่ต้องคุมให้ถูก:

- ตำแหน่งที่ปล่อยคือ "แทรกก่อนแถวนั้น" ถ้าย้ายลงข้างล่างต้องหักหนึ่ง เพราะตัวเองถูกดึงออกจากคิวก่อน
- **ห้ามวาดคิวใหม่ระหว่างลาก** ไม่งั้น DOM ที่กำลังลากหายกลางทางเมื่อเซิร์ฟเวอร์ส่งสถานะมาพอดี
  (แยกการวาดคิวออกเป็น `renderQueue()` เพื่อข้ามเฉพาะส่วนนั้น ส่วนอื่นยังอัปเดตปกติ)
- วางที่ตำแหน่ง 0 ถูกกันไว้เป็น 1 เพื่อไม่ให้เผลอไปแทรกทับเพลงที่กำลังเล่น (ใช้ปุ่ม ▶ แทน)
- ดัก `pointerup` ระดับเอกสารด้วย เผื่อปล่อยนิ้วนอกลิสต์ ไม่ให้สถานะลากค้างจนคิวไม่อัปเดตอีก
- ฝั่งเซิร์ฟเวอร์ `Room.move()` รับตำแหน่งใดก็ได้อยู่แล้ว จึงไม่ต้องแก้อะไร

ปุ่ม *สุ่ม* สลับเฉพาะเพลงที่ยังไม่ได้เล่น ไม่แตะเพลงที่กำลังเล่นอยู่

## ระดับเสียง

เสียงเป็นสถานะของห้อง ปรับจากเครื่องไหนก็มีผลที่ลำโพงของโฮสต์ มีสี่กลไกทำงานร่วมกัน:

1. **ปลด mute ก่อนตั้งค่า — เฉพาะเมื่อเสียงมากกว่า 0** mute กับระดับเสียงเป็นของแยกกันใน
   YouTube player ถ้ายัง mute อยู่ `setVolume` จะตั้งค่าให้จริงแต่ไม่มีเสียงออก (Chrome บังคับ
   mute ตอน autoplay) แต่ **ที่ระดับเสียง 0 ตัว player รายงานว่าตัวเองอยู่ในสถานะ mute** ถ้าเผลอ
   สั่ง `unMute()` ตรงนั้น YouTube จะคืนระดับเสียงเดิมที่จำไว้กลับมา เสียงจะโผล่มาเป็นจังหวะทุกครั้ง
   ที่ `sync()` ทำงาน จึงต้องปล่อยให้ 0 คง mute ไว้
2. **สะกิดให้ player เอาค่าไปใช้จริง** — บางเครื่อง `setVolume` เก็บค่าให้แต่ไม่ส่งผลกับเสียง
   ที่ออกลำโพงจนกว่าจะ **เริ่มเล่นใหม่** (อาการคือปรับ 1-100 แล้วดังเท่ากันหมด ต้องกดหยุดแล้วกดเล่น
   เองทุกครั้ง) การสลับ `mute()`/`unMute()` ไม่พอสำหรับเครื่องแบบนี้ จึงต้อง `pauseVideo()` แล้ว
   `playVideo()` ให้อัตโนมัติ (ห่างกัน 80 มิลลิวินาที) เงื่อนไขสำคัญคือ:
   - สะกิด **เฉพาะเมื่อค่าเปลี่ยน** ไม่งั้น `sync()` รอบ 2 วินาทีจะทำให้เพลงสะดุดตลอด
   - หน่วง 200 มิลลิวินาทีหลังค่านิ่ง ลากผ่านหลายค่าจึงสะกิดครั้งเดียวที่ค่าสุดท้าย
   - ไม่สะกิดตอนห้องสั่งหยุดเพลง และไม่สะกิดที่ระดับ 0
   - ตำแหน่งเพลงไม่หลุด เพราะเซิร์ฟเวอร์เป็นเจ้าของเวลา และช่องว่าง 80 มิลลิวินาที
     ไม่ถึงเกณฑ์ 1.2 วินาทีที่จะสั่ง seek แก้ drift
3. **อ่านค่ากลับมาตรวจ** — หลังสั่ง 300 มิลลิวินาที อ่าน `getVolume()` มาเทียบ ถ้าไม่ตรงก็สั่งซ้ำ
   ป้ายข้างแถบเสียงบนเครื่องโฮสต์โชว์ค่าที่ player รายงานตลอด (สีเทาเมื่อตรง สีเหลืองเมื่อไม่ตรง)
4. **`volumeSeq`** — เครื่องที่เพิ่งลากแถบเสียงจะยึดค่าของตัวเองไว้จนกว่าเซิร์ฟเวอร์จะบันทึกจริง
   (สังเกตจาก `volumeSeq` เดินหน้า) ไม่งั้น `sync()` รอบถัดไปจะเอาค่าเก่าจากเซิร์ฟเวอร์มาทับ
   ทำให้ปรับเสียงแล้วเหมือนไม่มีอะไรเกิดขึ้น

## เพิ่มเพลงและ playlist

ช่องเดียวทำสองหน้าที่ — **พิมพ์ชื่อเพลงคือค้นหา วางลิงก์คือเพิ่มทันที**

- **ค้นหาด้วยชื่อ**: พิมพ์ชื่อเพลง (ไทยหรืออังกฤษ) แล้วกด Enter จะได้ผลค้นหาพร้อมภาพปก
  ความยาว และชื่อช่อง กดปุ่ม *+ เพิ่ม* ทีละเพลงได้เลย แผงยังเปิดอยู่ให้เลือกต่อได้หลายเพลง
  ผลค้นหาอ่านจาก `videoRenderer` ใน JSON ของหน้าค้นหา YouTube ไม่ต้องใช้ API key
  และเก็บแคชไว้ 5 นาที (คำค้นซ้ำตอบใน ~15 มิลลิวินาที เทียบกับ ~1.2 วินาทีครั้งแรก)
  ตัดถ่ายทอดสดกับ Shorts ออกโดยดูจากการไม่มีความยาวคลิป
- วางลิงก์คลิปเดียว: ระบบ**ตรวจก่อนเพิ่ม** ว่าฝังเล่นได้จริงไหม ถ้าเจ้าของปิดการฝังจะไม่เพิ่มเข้าคิว
  แต่ขึ้นแถบแจ้งให้เลือกได้ว่าจะ *เพิ่มเข้าคิวอยู่ดี* (เผื่อการตรวจผิดพลาด)
- **เจอคลิปที่ฝังไม่ได้ ระบบหาเวอร์ชันที่เล่นได้มาเสนอเอง** ทั้งตอนตรวจก่อนเพิ่มและตอนเจอ error
  ระหว่างเล่นจริง โดยตัดชื่อเพลงให้สั้นลง (ตัดวงเล็บ, `[...]`, `feat.` ออก) แล้วค้นหา
  คัดคลิปเดิมทิ้ง ตรวจ 8 ตัวแรกว่าฝังได้ไหม แล้วส่งที่ผ่านสูงสุด 5 รายการให้ทุกเครื่องเห็นตรงกัน
  ชื่อของคลิปที่ปิดการฝังต้องอ่านจากหน้า watch เพราะ oEmbed ไม่ยอมบอกชื่อ
- วางลิงก์ `playlist?list=...`: เพิ่มทั้งชุด สูงสุด 100 เพลงแรก และคัดเพลงที่ฝังไม่ได้ออกให้เอง
  แล้วสรุปให้ว่าเพิ่มไปกี่เพลง ข้ามไปกี่เพลง
- ลิงก์ `watch?v=...&list=...` (มีทั้งคลิปและ playlist) ถือว่าต้องการคลิปนั้นคลิปเดียว

การตรวจใช้ oEmbed ของ YouTube (คลิปที่ปิดการฝังตอบ 401/403) ไม่ต้องใช้ API key
ถ้าตรวจไม่สำเร็จเพราะเน็ตขัดข้อง ระบบจะปล่อยให้เพิ่มไปก่อนแล้วอาศัยการดักตอนเล่นจริงเป็นด่านสุดท้าย

## บทบาทในห้อง

| | โฮสต์ (ลำโพง) | รีโมท |
|---|---|---|
| โหลด YouTube player | ใช่ — เสียงออกที่นี่ | **ไม่โหลดเลย** จึงไม่มีเสียงซ้อนและไม่กินเน็ต |
| เพิ่ม/ลบ/ข้ามเพลง, เลื่อนเวลา | ได้ | ได้ (ถ้าโฮสต์ไม่ล็อกสิทธิ์) |
| ปรับเสียงลำโพง | ได้ | ได้ — ระดับเสียงเป็นสถานะของห้อง ปรับจากเครื่องไหนก็มีผลที่ลำโพง |
| ล็อกสิทธิ์ให้เฉพาะตัวเอง | ได้ | ไม่ได้ |

- คนแรกที่เข้าห้องเป็นโฮสต์ ถ้าโฮสต์หลุด เครื่องถัดไปรับช่วงอัตโนมัติ
- กดปุ่ม **ย้ายลำโพงมาเครื่องนี้** เพื่อสลับว่าเครื่องไหนเป็นตัวปล่อยเสียง
- เครื่องรีโมทไม่มี player จึงไม่รู้ความยาวเพลง โฮสต์เป็นคนรายงานความยาวขึ้นเซิร์ฟเวอร์ให้
- การจบเพลงและการรายงานว่าเล่นไม่ได้ รับจากโฮสต์เครื่องเดียว และต้องแนบ `videoId` ให้ตรงกับ
  เพลงหัวแถว กันการข้ามซ้อนตอนเปลี่ยนเพลงพอดี

## ข้อจำกัดที่ควรรู้

- การกดการ์ดห้อง / ปุ่มสร้างห้อง นับเป็น user gesture ที่เบราว์เซอร์ต้องการก่อนเล่นเสียงอยู่แล้ว
  ถ้าเครื่องโฮสต์ยังถูกบล็อก จะมีปุ่ม *เบราว์เซอร์บล็อกเสียง — แตะเพื่อเล่น* โผล่ในแถบควบคุมให้กดเอง
- ถ้าเปลี่ยนตัวโฮสต์ระหว่างเพลง เครื่องใหม่ต้องโหลดคลิปตั้งต้น เสียงจะขาดไปหนึ่งจังหวะ
- **คลิปที่เจ้าของปิดการฝัง (embed) เล่นไม่ได้** — MV จากค่ายเพลงส่วนใหญ่ปิดไว้ ไม่ใช่แค่เว็บนี้
  แต่ทุกเว็บที่ฝัง YouTube เจอเหมือนกัน ตอนนี้ระบบคัดออกตั้งแต่ตอนเพิ่ม และถ้ายังหลุดมาได้
  จะจับ error 101/150 ตอนเล่นแล้วเอาเพลงนั้นออกจากคิวพร้อมแจ้งทุกเครื่อง
  ทางออกคือหาคลิปอื่นของเพลงเดียวกันที่ฝังได้ (มักเป็นเวอร์ชัน auto-generated ของช่อง Topic,
  lyric video หรือคลิป audio) หรือกดปุ่ม *เปิดบน YouTube* ดูเอง
- สถานะห้องเก็บในหน่วยความจำ รีสตาร์ทเซิร์ฟเวอร์แล้วคิวหาย
  (ถ้าอยากให้จำคิวได้ ต่อ SQLite เพิ่มที่ `app/room.py`)

## ต่อยอดได้อีก

- เก็บเพลย์ลิสต์ลง SQLite ให้ห้องเดิมกลับมาเล่นต่อได้
- โหมดจอใหญ่ + 3D audio visualizer ด้วย Three.js สำหรับเครื่องที่ต่อทีวี
- โหวตข้ามเพลง (ต้องเกินครึ่งห้องถึงข้าม) แทนการให้ทุกคนกดข้ามได้เอง
- ตรวจ `status.embeddable` แบบแม่นยำ และค้นหาแบบทนต่อการเปลี่ยนโครงสร้างหน้าเว็บ
  (ต้องใช้ YouTube Data API key — โควตาค้นหา 100 หน่วยต่อครั้ง ได้ราว 100 ครั้งต่อวัน)
- อ่าน playlist เกิน 100 เพลง (ต้องตาม continuation token ต่อ หรือใช้ API)
- ลากสลับลำดับคิวด้วยเมาส์ (ตอนนี้ใช้ปุ่ม ▶ / ⤒ แทน)
- deploy ขึ้น Fly.io เพื่อให้เพื่อนนอกวง LAN เข้าร่วมได้
